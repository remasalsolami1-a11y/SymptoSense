## Model Details

| | |
|---|---|
| **Algorithm** | Bernoulli Naive Bayes |
| **Library used for training** | scikit-learn |
| **Runtime inference** | Pure Python (no scikit-learn dependency in production) |
| **Model type** | Multi-class probabilistic classifier |
| **Input** | Binary vector of 12 reported symptoms |
| **Output** | Probability distribution over 15 candidate conditions |
| **File size** | `ml_model.json` (~15 KB, learned parameters only) |

### Why Naive Bayes?

Naive Bayes was chosen for three reasons appropriate to this project's scale and constraints:
1. **Performs well on small, sparse, binary feature data** — exactly the shape of this dataset (12 binary symptom flags).
2. **Fully interpretable** — every prediction can be traced back to a simple, auditable probability calculation, which matters for a health-adjacent tool where opaque predictions are a liability.
3. **Lightweight to deploy** — the trained parameters export to a small JSON file and require no ML framework at runtime, keeping the production bot's dependencies minimal.

---

## Intended Use

- **Primary use:** Cross-checking a patient's self-reported symptoms against learned statistical patterns, displayed alongside (not instead of) the LLM's own reasoning, inside a symptom-awareness Telegram bot.
- **Intended users:** General public seeking preliminary, non-diagnostic health awareness information.
- **Out-of-scope use:** This model must **not** be used for actual medical diagnosis, treatment decisions, or in any clinical setting. It is a health-literacy tool, not a diagnostic device.

---

## Training Data

The model is trained on a **synthetically generated dataset**, not real patient records (no real patient data was available or used).

**Generation process:**
1. A curated knowledge base defines 15 common primary-care conditions, each mapped to its typical symptom set (e.g., Migraine → {headache, nausea, dizziness}).
2. For each condition, 200 synthetic patient samples were generated by:
   - Randomly sampling a **partial subset** of that condition's typical symptoms (simulating that real patients rarely report every textbook symptom).
   - Injecting a stray, unrelated symptom in ~15% of samples (simulating real-world reporting noise).
3. This produced **3,000 labeled samples** (15 classes × 200 samples), split 80/20 into train/test sets, stratified by class.

| | |
|---|---|
| Training samples | 2,400 |
| Test samples | 600 |
| Number of classes | 15 |
| Number of features | 12 (fixed symptom vocabulary) |

**Feature vocabulary (12 symptoms):** headache, fever, cough, chest pain, nausea, fatigue, shortness of breath, dizziness, joint pain, stomach pain, chills, red eyes.

**Classes (15 conditions):** allergic rhinitis, anxiety-related symptoms, asthma flare-up, bronchitis, common cold, conjunctivitis, dehydration, flu, food poisoning, gastroenteritis, migraine, muscle strain, pharyngitis, sinusitis, vertigo.

### Reading the results

- The model performs strongest on conditions with **distinctive symptom signatures** (e.g., allergic rhinitis, flu, migraine — high precision).
- It performs weakest on **gastroenteritis vs. food poisoning** (0.41 and 0.51 precision respectively) — these two conditions share almost identical symptom sets in the underlying knowledge base, which is medically realistic: they are genuinely difficult to distinguish from symptoms alone, even for clinicians, without lab tests or a detailed history.
- This is treated as an honest finding, not a flaw to hide — it demonstrates the model is learning real symptom overlap patterns rather than memorizing labels.

## Limitations

1. **Synthetic training data.** The model has never seen a real patient. Its "knowledge" is bounded by the curated knowledge base used to generate training examples, not real-world clinical variation.
2. **Small, fixed symptom vocabulary.** Only 12 symptoms are modeled. Any symptom outside this list is invisible to the model.
3. **Naive independence assumption.** Naive Bayes assumes symptoms are conditionally independent given the condition, which is a simplification — in reality, symptoms often co-occur non-independently (e.g., fever and chills).
4. **No demographic features.** The current model does not use age or sex as inputs, despite these being clinically relevant to differential diagnosis.
5. **Confusable condition pairs.** As shown in the evaluation, conditions with near-identical symptom profiles (gastroenteritis/food poisoning, common cold/sinusitis) are harder to separate — this is a known, expected limitation rather than a bug.

---

## Ethical Considerations

- **Not a medical device.** This model is explicitly framed to end users as a statistical cross-check for awareness, alongside a clear disclaimer that it does not replace professional medical consultation.
- **No personally identifiable data.** All symptom logs used for the bot's own analytics (separate from this model's *training* data) are stored against a one-way hashed user identifier, never a real name or Telegram ID.
- **Transparency.** The model's exact probability output is shown to the user (not hidden behind a vague "AI says..." framing), and its accuracy is disclosed in-product.
